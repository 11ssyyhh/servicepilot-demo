# 可观测与安全边界

## 可观测设计

每次会话生成独立 `trace_id`，覆盖 Agent、Skill、MCP 工具、LLM、RAG 与审批事件，产出五类证据：

- **Trace**：`output/trace.jsonl`，Span 类型包括 `agent`、`skill`、`mcp.tool`、`llm`、`rag.retrieve`、`approval`
- **Log**：`output/logs.jsonl`，结构化记录意图路由、任务规划、失败原因、审批与审计事件
- **Metrics**：`output/metrics.json`，会话数、Agent 调用、工具成功率、LLM Token、成本、端到端延迟
- **Session**：`output/session.json`，会话状态快照（消息已脱敏）
- **Summary**：`output/summary.json`，审批、工单、执行记录与服务报告

## 评估与回放

- `python evaluate.py`：基于 `eval_dataset.json` 的 Golden/Badcase 回归，输出意图准确率、闭环解决准确率、工具成功率、延迟与成本。
- `python replay.py [session_id]`：还原「输入 → 任务拆解 → 工具调用 → 审批/证据 → 输出 → 满意度」。
- `python approval_server.py`：人工审批 Web 界面，支持通过/拒绝并写入审计。

## 安全边界

| 级别 | 范围 | 示例 | 是否自动执行 |
|---|---|---|---|
| L0 | 只读 | 订单查询、知识检索、历史案例 | 自动 |
| L1 | 低风险写 | 修改地址、工单标签 | 自动（幂等+留痕） |
| L2 | 高风险写 | 退款、销户、大额操作 | 必须人工审批 |
| L3 | 极端风险 | 仅生成方案，不执行 | 审批 + 方案 |

## 关键机制

- **幂等**：写操作携带 `idempotency_key`，重复调用返回同一结果。
- **回滚**：退款前记录回滚点，`RollbackOperation` 可恢复原状态。
- **审批**：审批记录含方案、证据、审批人、时间与原因；拒绝必须附原因并转人工。
- **审计**：Agent/Skill/MCP/LLM 调用、权限校验、审批与回滚全部留痕。
- **数据合规**：手机号、邮箱、地址等在证据文件中自动脱敏；Mock 数据为合成数据。
