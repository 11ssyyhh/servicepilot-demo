业务痛点

传统客服为什么做不成“自主闭环”

01

单 Bot 能力边界有限

复杂问题需要识别意图、查知识、调业务系统、校验结果，单一机器人无法可靠编排，长链路容易中断。

02

高风险操作依赖人工

退款、销户等高风险动作没有明确的审批门禁、幂等与回滚机制，自动化落地阻力大。

03

过程不可追溯

客服处理过程缺少 Trace、日志、指标与审计记录，出问题后难以回放定位。

04

经验难沉淀复用

优秀客服话术、业务规则与历史案例散落，无法转化为可评估、可迭代的 Agent 资产。

痛点ServicePilot 用 Agent Infra 方式把客服流程工程化

安全与治理

L0-L3 风险管控 + 人工审批 + 幂等回滚

等级含义示例机制
L0只读诊断订单查询自动执行
L1低风险自动地址修改自动执行 + 留痕，失败转人工
L2灰度 + 审批退款处理人工审批通过后幂等执行，可回滚
L3极端风险销户 / 大额转账仅生成方案，不执行

审批双路径

通过后自动续跑执行退款；拒绝后转人工工单，两条路径均可审计。

幂等键

写操作携带 idempotency_key，重复提交返回同一结果。

回滚点

退款前保存订单状态，RollbackOperation 可恢复。

安全与治理审批台：approval.html + approval_server.py
可观测与审计

Trace / Log / Metrics / Session / Summary

全链路 Span

Agent、Skill、MCP 工具、LLM、RAG、审批事件统一写入 trace.jsonl，每个会话有独立 trace_id。

结构化日志

意图路由、失败原因、审批请求、审计事件均以结构化 JSON 记录，便于检索。

聚合指标

会话数、工具成功率、LLM Token、成本、端到端延迟写入 metrics.json。

回放与脱敏

replay.py 从输入还原到满意度；session 快照自动对手机号、邮箱、地址脱敏。
